# Yeti — implementation plan

Spec: [`../specs/2026-11-18-yeti-design.md`](../specs/2026-11-18-yeti-design.md) (approved by
Tim 2026-11-19, with the font call: no webfont, a standard reliable stack).
Branch: `redesign/yeti`. One commit per task, in this order.

## The rule that shapes every task

Only the header, footer, show header, setlist and settings panel branch per edition. Everything
else (forms, home, stats, songs, venues, charts) renders the same markup in 3.0 and 2.0. So:

- 3.0's changes to a shared component go in CSS under `[data-experience="fancy"]`, reached
  through a stable class hook added to the markup. 2.0 has no rule for the hook, so it doesn't
  move.
- Where 3.0's *layout* differs (Home, the show header), the page branches
  `experience === "fancy"` and 2.0 keeps today's JSX verbatim.
- Shared chart colors go through tokens that 2.0/1.0 alias to today's values.

**Gate after every task:** `npm run typecheck`, `npm test`, and the 2.0/1.0 comparison: both
editions, light and dark OS, 390 and 1280, sixteen pages, shot on `origin/main` (worktree,
port 3200) and on the branch (port 3100) the same day, byte-compared. `/stats/current-gaps`
renders nondeterministically even on `main`; a diff there gets reshot before it counts.

## Tasks

1. **Tokens and type.** `globals.css`: the fancy token block (Yeti palette, roles, `--foil`,
   `--gap-near`, `--graphite`), the 2.0/1.0 aliases on bare `:root`, the system rounded stack for
   `--type-*` under fancy; delete the slate media block and `[data-theme]` block. Fancy base
   overrides: night background with the snow glow, heading weights, foil focus ring, selection,
   `.link`. `layout.tsx` drops `localFont`; `app/fonts/` deleted. Contrast gate rewritten.
2. **Dark-only plumbing.** Delete `lib/theme.ts` (+ test) and `themeScript`; `allowsTheme`
   goes; the settings panel loses the appearance row in every edition (its 2.0/1.0 line
   "appearance applies in the 3.0 experience" stops being true); the 3.0 blurb changes. Test:
   a stale `data-theme="fog"` changes no token.
3. **Chrome.** `HeaderFancy` (glass bar, active pill, shelf search), `FooterFancy` (well),
   mobile sheet and search box via fancy CSS, the settings popover's fancy branch with the
   segmented edition picker. `generateViewport` sets `theme-color` night on 3.0 only.
4. **Material components.** `app/_components/yeti.tsx`: `Pack` (card + bubble, `empty`),
   `DateTile`, `LabelSticker`, `PlainTag`, `RowSticker`; their CSS lifted from
   `yeti-theme.html`.
5. **Page forms.** Hooks + fancy CSS for `forms.tsx` (section heads, ledger, figures,
   contents), `page-chrome.tsx` (page head, filters, folio, nil state), the pen (straight rule,
   upright note, circle/arrow hidden), song page (figures, table, tags), stats, venues, blog
   prose. Fancy-only branches: Home (masthead, totals, tonight's pack, two columns when wide),
   the show header (date tile, nameplate, one primary; the empty pack without a setlist), the
   fancy setlist (rows on frost rules, plain tags, the live row sticker).
6. **Charts' colors.** `--foil`/`--gap-near` in `the-shelf.tsx`, Most Overdue in
   `stats/page.tsx`, the gap sparkline in `song/charts.tsx`, `.overdue`; `--graphite` for chart
   tape and hubs; color-naming captions branched per edition.
7. **Icons and OG.** `icon.svg`, `apple-icon.tsx`, `opengraph-image.tsx`, `favicon.ico`.
8. **The app's name.** The six `/listen-links` lines, the deep-link doc's prose, the tests,
   the `match.ts` comment.
9. **Docs.** README (three editions, role table, screenshot note, architecture line), and
   `git grep -i "fog\|slate"` down to intentional hits.

Then: 3.0 screenshots at 390 and 1280 (home, a show with and without a setlist, a song, /stats,
/stats/oracle, /venues, /listen-links, a blog post), keyboard focus, reduced motion, a stale
`ga-theme=fog`; push the branch and open the PR (Tim judges on the preview; merging is his).
